# Fable/watch

Three switchable watch faces for the TAKTO ONE on-device screen, one engine,
one source of truth, verified as images before anything is flashed.

- **[FACE-ENGINE.md](FACE-ENGINE.md)** - the architecture, what each face is,
  and the honest gaps (read this one first).
- **[FRAME-BUDGET.md](FRAME-BUDGET.md)** - what the faces cost and what is
  still unmeasured.
- **[FLASH-RUNBOOK.md](FLASH-RUNBOOK.md)** - how to put it on the board and
  what to check.
- **[canon/](canon/)** - the imported Ferro design canon, with provenance.

**The firmware compiles and is NOT flashed.** Everything visual here is a host
render produced by the same C++ the Teensy runs, driven by a simulated hand
feed. It is not a photograph of the panel and is not evidence about on-device
behaviour.

## Quick start

```bash
cd host
make            # the renderer + the thesis-face fidelity gate
make test       # Thesis pixel fidelity + every face/state/colorway painted
make sheets     # the whole review set into ../out/
make catalog    # regenerate ../catalog.json from the C++ registry
./watch_render --list      # faces, colorways, notes
./watch_render --duty      # the frame-budget measurement that matters
```

## Where the pieces live

| what | where |
|---|---|
| the engine and the three faces | `faces/` |
| the sketch that runs it | `Working/Firmware-and-Code/DeviceFirmware/` (reaches `faces/` by symlink) |
| the bridge command | `Fable/web/tools/teensy_bridge.py`, contract in `Fable/web/DATA_CONTRACT.md` |
| the web selector | `Fable/web/app/src/views/operator.js`, Tools drawer, "Watch face" |
| the Android selector | `Fable/android/.../ui/watch/`, reachable from Settings |
| the specs | `ecosystem_test.py` section M, `firmware_conformance_test.py` section 9 |

## The rule that keeps it consistent

`catalog.json` is **generated** from the C++ face registry and is the only face
list the bridge, the web console and the Android app are allowed to read. Add a
face or a colorway, run `make catalog`, or every other surface goes stale. The
ecosystem spec asserts the bridge serves that exact file.

## Asset provenance

Everything in `out/` is generated by `make sheets` from `faces/` at the commit
you run it on, using the mock hand feed in `host/sim_feed.h`. Regenerate rather
than reuse: an old render of living software is exactly the staleness the
repo's live-asset rule exists to prevent. The contact sheets stamp themselves
`MOCK FEED` for the same reason.
